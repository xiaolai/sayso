# Parity

Behaviour is shared through fixtures, not code. CI fails when an implementation disagrees with a fixture, or when a
fixture is not run by an implementation that must run it.

## Components and capabilities

The components are `credentials`, `mint`, `session`, `pcm16` and `said-guard`. `fixtures/capabilities.json` is
checked-in policy: for each implementation, the components it must implement and the capabilities it must declare.
Go and Swift implement all five. Swift must declare `spellout:<lang>` for `ar de es fr hi it ja ko pt`, the voice
languages of Checkmate other than `en` and `zh` (which use the said guard's own tables); Go declares none. Swift's
declaration is its `saidGuardSpellOutLanguages`, so the two cannot drift apart. A later implementation may implement
fewer components and is held to exactly the ones it declares, and to all of their fixtures.

`capabilities.json` also records the said guard's revision, `saidGuardVersion` (spec/said-guard.md). Each suite fails
when its constant (Go `saidguard.Version`, Swift `saidGuardVersion`) differs from it, so a change that raises the
revision raises it in the policy and in every implementation together.

## Results and checks

`fixtures/MANIFEST.json`, generated by `tools/manifest.py` and checked in, lists every fixture id with its file,
component and `requires`, and the total. Each test suite writes `results-<lang>.json`:
`{"implementation", "components", "capabilities", "results": {id: outcome}}`, where an outcome is `pass`, `fail`,
or `exempt`. `tools/parity.py` fails when:

- `MANIFEST.json` differs from a fresh scan of `fixtures/`, has a duplicate id, or counts zero;
- a declared component or capability falls short of what `capabilities.json` requires;
- a result set misses an id of a component it declares, contains an unknown id, or contains an id twice;
- an outcome is `fail`;
- an outcome is `exempt` where no exemption applies. Only a **true** said-guard expectation whose `requires` names
  a capability the implementation does not declare may be exempt: every implementation must return false on every
  false fixture, so a capability gap costs a regeneration, never a false acceptance;
- a fixture folder a suite reads is missing (a missing folder is an error, never an empty list).

The Go module's published archive contains only `go/`, so fixture tests run only in this repository's checkout,
reading `../fixtures` through the manifest, and fail when it is absent.

## Tags

`vX.Y.Z` releases the Swift package (SwiftPM reads root tags), `go/vX.Y.Z` the Go module (Go's convention for a
module in a subfolder). Both are cut from one commit when fixtures change.
